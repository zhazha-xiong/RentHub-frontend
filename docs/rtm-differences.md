# 原型 vs 需求跟踪矩阵（RTM）差异台账

> 来源：`第8组_基于AI智能体的房屋租赁系统_RentHub智能房屋租赁平台_需求跟踪矩阵.xlsx`
> 主表 `设计用RTM` 共 **115 条功能点 / 16 个页面模块**，另有 16 张带编号的设计图（`图1`~`图16`）。
> 本文只记录**与 RTM 的差异与取舍**，不改动 xlsx 本身（矩阵由 PM 维护）。

## 1. 我们更合理的（**不写进 RTM 表格**，在此存档理由）

| # | 我们的做法 | RTM 情况 | 理由 |
|---|---|---|---|
| 1 | 详情页 `.info` 区加 `position: sticky` 跟随滚动 | RTM 未提及（图5 是普通 aside） | 长页面下滑看设施时，价格与下单按钮常驻，转化更直接 |
| 2 | 列表「更多筛选」增加「近地铁」复选 | RTM 29 只有「房屋类型 / 朝向 / 电梯房」 | 租房决策里"到地铁步行距离"与电梯同等重要，且后端字段现成 |
| 3 | 假后端支持「一句话搜索」解析 + 分层放宽 | RTM 23 要求回车后跳 AI 找房页 | 真后端接入前，列表页不出现 0 结果是兜底；正式流程仍按 RTM 走 AI 页 |
| 4 | 列表统计同时给「全站在架数」与「今日新上」 | RTM 31 只要一个数字 | 两个数字语义不同（全站规模 vs 增量），分开写更利于判断热度 |

## 2. 不采纳的 RTM 条目

| 条目 | RTM 原文 | 决定 | 理由 |
|---|---|---|---|
| 33 / 69 | 卡片右上角**心形**按钮，未收藏描边、已收藏主色实心 | 不采纳，沿用 v2 的文字按钮「收藏 / 已收藏」 | 文字比图标更明确（尤其中文语境下的"收藏"），且与 v2 美术一致；图标方案留作图4 的备选 |

## 3. 待拍板 / 已拍板

| 冲突点 | 结论 |
|---|---|
| 详情页标题字号（RTM 41 要求 26px）与「sticky 一屏」 | **已定方案 A**：26px，同时压缩 `.spec` 行距与商家块间距；矮屏（≤840px）降为 20px |
| 面包屑前两级是否带筛选参数 | 按 RTM 34 原文，只「返回列表页」不带参数；"返回保留筛选"作为列表页 URL 状态化需求单列 |
| 商家订单默认签页（RTM 97 待确认 / 现为全部） | 待定：建议回「待确认」+ 支持 `?tab=` 深链，供 E2E 指定 |
| 订单号格式（RTM 63 `RH20261104001` / 现 `20261105-002001`） | 待定：改动面涉及 mock 生成规则与全部断言 |

## 4. 已按 RTM 对齐的批次

### P1（视觉 / 文案）

| 条目 | 对齐内容 |
|---|---|
| 41 | 详情页标题 26px；矮屏降 20px；`.spec` 行距、商家块、问问 AI 间距压缩以保持一屏 |
| 34 | 面包屑改为「区域 / 小区 / 房源」三级，前两级可点击回列表 |
| 37 | 租约四项（付款方式、最短租期、看房、车位）缺失时显示「未填写」；规格表 8 项仍用 `—`（RTM 42 未规定缺失态） |
| 31 | 列表统计改为「N 套符合条件 · 今日新上 M 套」，随筛选变化 |
| 63 / 84 / 110 | 状态标签统一三色：待确认/已出租/待审核=橙，在架/已确认/已通过=绿，已完成/已取消/已下架/已驳回=灰 |
| 74 | 通知时间改为相对时间（10 分钟前 / 今天 09:12 / 昨天 … / 更早显示日期），**文案由后端给 `created_label`**，前端不按浏览器时钟推断 |

> 关于 `created_label`：与 `published_label` 同一思路——假后端的"当前时间"固定为 2026-11-05，前端用浏览器真实时钟算相对时间会得出负数。接口补字段的说明见 `docs/contract-supplements.md`。
